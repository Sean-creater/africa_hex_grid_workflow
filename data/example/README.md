# Example output (SYNTHETIC — not real data)

Every file in this directory whose name contains `SYNTHETIC` is a fabricated
toy dataset generated by `generate_toy_example.py`, with a fixed random seed.
It exists **only** to show the schema (column names, dtypes, file formats)
that `africa_hex_grid_workflow.pipeline.GridPipeline` produces for a real
city. Building heights, volumes, population counts, and land cover
percentages in these files are random numbers, not measurements — do not use
them for any analysis.

Files:

- `toyville_SYNTHETIC_grid_250m_hex_enriched.{shp,dbf,shx,prj,cpg}` — the
  per-hexagon grid with every attached data column, in Shapefile format.
- `toyville_SYNTHETIC_grid_250m_hex_enriched.csv` — the same data, tabular,
  no geometry.
- `toyville_SYNTHETIC_grid_250m_hex_enriched.geojson` — the same data, with
  geometry, in GeoJSON.
- `toyville_SYNTHETIC_grid_boundary.geojson` — the dissolved outline of all
  hexagons (a single Polygon or MultiPolygon), the artifact intended for
  handing off to other modules that need the exact analysis extent.

## Regenerating this toy example

```bash
python data/example/generate_toy_example.py
```

## Generating a real example

To generate a real (non-synthetic) example for an actual city, obtain the
input raster and boundary data described in the top-level README, run
`clip_country_rasters.py` once for the relevant country, then run:

```bash
python -m africa_hex_grid_workflow.pipeline \
    --aoi-mode city --aoi-name "Kumasi" \
    --data-dir /path/to/your/data \
    --country-tif-dir /path/to/your/data/00_country_TIF \
    --country-boundaries /path/to/africa_boundaries.gpkg \
    --city-boundaries /path/to/agglomerations.gpkg \
    --country-iso3 GHA
```

See the top-level README for full setup instructions.
